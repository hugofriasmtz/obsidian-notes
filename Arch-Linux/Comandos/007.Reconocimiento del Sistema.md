# Reconocimiento y Auditoría del Sistema en Linux

El **reconocimiento de sistemas** (*System Reconnaissance / Baseline Discovery*) es la primera tarea que realiza un administrador de sistemas, un ingeniero DevOps o un analista de seguridad al entrar por primera vez a un servidor (local, en la nube o vía SSH). Consiste en responder cuatro preguntas clave:  

1. *¿Dónde estoy parado?*  
2. *¿Qué hardware y sistema operativo tengo?*  
3. *¿Qué privilegios tengo?*  
4. *¿Cómo se está comportando el equipo en tiempo real?*

---

## 1. Primer Inicio de Sesión y Comprobación Inicial

Al acceder por primera vez a una terminal (por ejemplo, con el usuario **`hugofrias`**), el sistema suele mostrar el archivo `/etc/motd` (*Message of the Day*). Tras el mensaje de bienvenida, ejecutamos el reconocimiento de orientación inmediata:

### 1.1. ¿Quién soy y cuál es mi nombre de equipo?

```bash
whoami        # Devuelve tu nombre de usuario actual
hostname      # Nombre de la máquina en la red
hostname -I   # Muestra rápidamente las direcciones IP asignadas
```

### 1.2. Configuración de fecha, hora y zona horaria

La sincronización temporal es crítica para los logs, certificados SSL y bases de datos:

```bash
date
```

Para una inspección profunda del reloj y sincronización NTP:

```bash
timedatectl
# Muestra si el reloj local está sincronizado y la zona horaria (Time zone)
```

### 1.3. Resumen de interfaces de red activas

Para ver las IPs y el estado de los enlaces de red de un solo vistazo:

```bash
ip -br a
# Salida rápida: muestra interfaz (eth0, wlan0), estado (UP/DOWN) y la IP
```

## 2. Información del Sistema y Tiempo de Actividad (*Uptime*)

Aquí recopilamos la ficha técnica del sistema operativo y su estabilidad histórica.

### 2.1. ¿Qué distribución y versión de Linux está corriendo?

El estándar universal en Linux moderno es consultar `/etc/os-release`:

```bash
cat /etc/os-release
```

Si la máquina tiene instalado `systemd`, el comando preferido para un resumen completo es:

```bash
hostnamectl
# Salida: Sistema Operativo, Kernel, Arquitectura y Nombre del Host
```

### 2.2. Kernel y arquitectura del procesador

El comando universal es `uname` (*Unix Name*):

* **`-a`** (*all*): Muestra toda la información junta (kernel, arquitectura, fecha de compilación).
* **`-r`** (*kernel release*): Versión exacta del núcleo de Linux.
* **`-m`** (*machine*): Arquitectura del procesador (`x86_64`, `aarch64`/ARM).

```bash
uname -a
uname -r
```

### 2.3. Especificaciones del procesador (Hardware CPU)

```bash
lscpu
# Muestra modelo de procesador, número de núcleos (cores), hilos y velocidad
```

---

### 2.4. Tiempo de actividad (*Uptime*) y reinicios históricos

¿El servidor lleva encendido años o se reinició hace 5 minutos?

```bash
uptime
# Salida de ejemplo:
# 14:20:10 up 45 days, 3:12,  2 users,  load average: 0.15, 0.08, 0.01
```

* **`uptime -p`** (*pretty*): Muestra el tiempo encendido en formato legible para humanos:

  ```bash
  uptime -p
  # Salida: up 6 weeks, 3 days, 3 hours, 12 minutes
  ```

#### ¿Cuándo fue el último reinicio y quién lo provocó?

```bash
# Fecha exacta del último encendido:
who -b

# Historial de los últimos reinicios del sistema:
last -x reboot | head -n 5
```

## 3. Recopilación de Detalles de Usuario y Grupos

Debes auditar qué nivel de control tiene el usuario **`hugofrias`** y quién más habita la máquina.

### 3.1. Identidad y privilegios del usuario

```bash
# Ver UID, GID y todos los grupos asignados a hugofrias:
id

# Ver únicamente los nombres de los grupos:
groups
```

### 3.2. ¿Tengo permisos de administrador? (La prueba de fuego)

El reconocimiento más importante: saber qué comandos puedes correr con `sudo` sin necesidad de adivinar:

```bash
sudo -l
```

*Si la salida dice `(ALL : ALL) ALL`, tienes control total de la máquina.*

### 3.3. Variables de entorno activas

Las variables definen rutas de binarios, configuraciones del sistema y a veces exponen secretos o tokens:

```bash
# Ver todas las variables del entorno actual:
env

# Inspeccionar específicamente el PATH (dónde busca programas la terminal):
echo $PATH

# Saber qué editor o terminal están configurados:
echo $SHELL
echo $EDITOR
```

### 3.4. Auditoría de usuarios conectados y accesos recientes

```bash
# ¿Quién está conectado en este instante y qué programa corre?
w

# Ver los últimos 5 inicios de sesión exitosos en el equipo:
last -n 5

# Ver cuándo fue la última vez que cada usuario inició sesión:
lastlog | grep -v "Never"
```

## 4. Supervisión del Rendimiento en Tiempo Real

Antes de ejecutar aplicaciones pesadas o si el servidor va lento, revisamos los tres pilares del rendimiento: **Memoria**, **Disco** y **CPU**.

### 4.1. Memoria RAM y Swap: `free`

Usa siempre la bandera **`-h`** (*human-readable*) para leer en Megabytes y Gigabytes:

```bash
free -h

```

**Cómo interpretar la salida:**

```text
               total        used        free      shared  buff/cache   available
Mem:            15Gi       3.2Gi       8.5Gi       120Mi       4.1Gi        12Gi
Swap:          2.0Gi          0B       2.0Gi
```

>[!WARNING]
> En Linux, la columna importante **no es `free`**, sino **`available`**. Linux usa la memoria libre para caché de disco (`buff/cache`), pero la liberará al instante si una aplicación la necesita. Si `available` está cerca de cero, el sistema se quedará sin RAM.

---

### 4.2. Espacio y particiones de disco: `df` y `lsblk`

* **`df -h`** (*Disk Free*): Muestra el porcentaje de uso de cada partición montada.

  ```bash
  df -h
  # Revisa la columna Use% buscando discos al 95% o 100% (causa común de fallos)
  ```

* **`lsblk`** (*List Block Devices*): Muestra el árbol de discos duros físicos, particiones y volúmenes LVM:

  ```bash
  lsblk
  ```

---

### 4.3. Monitor interactivo de CPU y Procesos: `top` (o `htop`)

Para ver qué proceso está devorando la máquina en vivo:

```bash
top
```

#### Atajos clave dentro de `top`

| Tecla | Acción |
| :---: | :--- |
| **`M`** | Ordenar la lista por consumo de **Memoria RAM**. |
| **`P`** | Ordenar la lista por consumo de **CPU** (por defecto). |
| **`k`** | Matar (*kill*) un proceso ingresando su PID. |
| **`1`** | Desglosar el uso de CPU núcleo por núcleo. |
| **`q`** | Salir de `top`. |

*(Si el servidor tiene instalado `htop`, úsalo; es una versión mucho más visual y navegable con el ratón o flechas).*

#### Entendiendo el *Load Average* (Carga promedio)

En `uptime` y en `top` verás 3 números: `load average: 0.20, 0.45, 0.60`.  
Representan el promedio de procesos en espera durante los últimos **1**, **5** y **15 minutos**:

* Si tienes **4 núcleos de CPU** y tu carga es **4.0**, tu procesador está al 100% de capacidad óptima.
* Si supera el número de núcleos (ej. carga 8.0 en 4 núcleos), el equipo está sobrecargado y las tareas hacen cola.
